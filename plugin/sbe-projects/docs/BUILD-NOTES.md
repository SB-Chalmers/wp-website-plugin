# New SBE site – build notes

Technical notes for whoever maintains the site: how it's built, which settings were changed and where to find them. For the everyday "how do I add a post/project/person" guide, see [EDITOR-GUIDE.md](EDITOR-GUIDE.md).

Site: local WordPress Studio site "new-sustainable-built-environments" (WP 7.1, theme Twenty Twenty-Five, SQLite), to be synced to sb.chalmers.se.

## Where the documentation lives
- `wp-content/plugins/sbe-projects/docs/` (this folder): `README.md`, `BUILD-NOTES.md` (this file), `EDITOR-GUIDE.md`, `POSTS-AND-PROJECTS-TUTORIAL.md` (simple, non-technical tutorial for posts and projects only; keep it in step with EDITOR-GUIDE.md when the editor changes). It lives inside the custom plugin so it is included whenever plugins are pushed/pulled with Studio sync, and anyone who pulls the site into Studio or opens it in VS Code gets it.
- **These files are the master copies.** The editor guide used to have a master copy in a Claude doc ("SBE website – how to add content"); since 2026-10-08 it is no longer maintained, edit the files here only. (A copy of this file is also kept in the claude.ai project "Website", `claude/site-build-notes.md`, with an appendix of local DB details.)
- **Shown inside WordPress (since 1.15.0):** `includes/help.php` reads the Markdown files in this folder on every page load and renders them with Parsedown 1.7.4 (MIT, `includes/vendor/Parsedown.php` + licence), so the admin always shows the current files, no copy to update. (1) Dashboard → **Help** (top-level menu, `dashicons-editor-help`, position 26, capability `edit_posts`, page slug `sbe-help`): tabs **Quick tutorial** (`?doc=tutorial`, this tutorial), **Editor guide** (`?doc=guide`) and, for administrators only (`manage_options`), **Build notes** (`?doc=build`); footer line shows the file and its last-changed date. (2) Block editor (posts, projects, resources, pages; not the Site Editor): a `PluginSidebar` **Help** (? icon in the top bar, also ⋮ → Plugins; called "How to add content" until 1.23.0, renamed so it isn't confused with the Add content sidebar) with the quick tutorial and links to the full Help page (`assets/help-sidebar.js`, HTML passed in `window.sbeHelp` by `wp_add_inline_script`). Rendering: links to another doc file (e.g. `EDITOR-GUIDE.md`) point to its Help tab, h2–h4 get slug ids (`#add-a-post`), external links open in a new tab, tables are wrapped in `.sbe-help-table` (scrolls sideways in the sidebar), output passes `wp_kses_post()`. Styles: `assets/help.css`. **So: write the docs for editors; whatever is saved here is what they see.** Relative links between docs must use the bare file name to be rewritten.
- Files in the plugin folder can be opened by URL on the live site (e.g. `/wp-content/plugins/sbe-projects/docs/BUILD-NOTES.md`). Never put passwords, keys or personal data in these files.
- Most design settings below live in the **database** (global styles, templates, page content), not in files. They travel with a database push/pull, not with the docs folder.

## Focus rings (file, not database)
- **No black box after clicking or tapping a link** (2026-10-08): Twenty Twenty-Five's `style.css` outlines every focused element (`:where(.wp-site-blocks *:focus){outline-width:2px;outline-style:solid}`), so a clicked/tapped link (People, Resources, site title on phones…) kept a black box until you tapped elsewhere. `assets/focus.css` (enqueued site-wide by `sbe_focus_enqueue()` in `sbe-projects.php`) adds `.wp-site-blocks :focus:not(:focus-visible){outline:none}`: the ring still shows for keyboard (Tab) users, which matters for accessibility, but not after a mouse click or tap. To undo: delete the function and the file.

All stored in the user global styles (wp_global_styles post "Custom Styles"); change or revert in Site Editor → Styles.

- **Font: Manrope** (the theme default; checked 2026-09-29): body text `styles.typography.fontFamily` = `var:preset|font-family|manrope`, weight **300**, size Small; headings inherit Manrope. Fira Sans was tried earlier (it ships with Twenty Twenty-Five but is only registered in a style variation, so the user styles also register it in `settings.typography.fontFamilies.theme`; it stays in the font list). Change in Styles → Typography → Text.
- **Bold headings:** all headings use font weight 700 (`styles.elements.heading.typography.fontWeight`, theme default 400). Styles → Typography → Headings.

## Text width guidance
- Readable line length ≈ 60–80 characters. Manrope averages ~0.45 × font size per character (Fira Sans is similar, slightly narrower); Medium text ≈ 18px on wide screens → ~8px/char → ~650–700px max width for intro paragraphs.
- Use a **px** content width on text groups (acts as a maximum, so phones get full width), not % (stays proportional and becomes a thin column on phones).

## Publications (since 1.26.0, 2026-10-20)
- **Why:** publications were a pattern (`sbe/publications`, an h2 + a `sbe-publications` list typed into the text). Now they are a standard field on posts, projects and resources, edited in the sidebar like Read more links, shown in a fixed place and hidden when empty, and they can be added by pasting BibTeX (the usual way of citing in the division).
- **Field:** post meta `sbe_publications` on `post`, `project` and `resource` (`includes/publications.php`, `sbe_publications_post_types()`): array of `{title, url, authors, year, venue}` (all strings, REST schema with `additionalProperties: false`). `sbe_publications_sanitize()` drops rows without a title; `url` → `esc_url_raw`, the rest `sanitize_text_field`. Year is free text (e.g. "in press").
- **Sidebar panel "Publications"** (`PublicationsPanel` in `editor.js`, class `sbe-publications-panel`; in the Add content sidebar after Read more links, and as a Document panel when the full editor is on). Each publication shows as a summary (bold title, grey "Authors (Year)", italic venue) with **Edit** (opens the five fields: Title, Link (URL, optional), Authors, Year, Journal or conference) / **Up** / **Down** / **Remove**. **Add publication** appends an empty one and opens it. Order in the panel (since 2026-10-20 evening): intro line, **Paste BibTeX** textarea + **Add from BibTeX** button, with a green/red status line ("Added 2 publications…", "No publication found…"). then **Add publication**, then the list (newest added at the bottom). Publications whose title (case-insensitive) is already in the list are skipped. Panel is open by default only when it has entries.
- **BibTeX reader** `assets/bibtex.js` (own code, no library; `window.sbeBibtex.parse(text)`, registered as script `sbe-bibtex`, a dependency of `editor.js`): reads any number of entries (`@article{…}` / `@inproceedings(…)` …), braces/quotes/bare values, `#` concatenation and `@string` macros; skips `@comment`/`@preamble`. Mapping: title (outer braces removed, trailing period dropped); authors from `author` (else `editor`) split on top-level `and`, "Last, First" → "First Last", "Last, Jr, First" handled, `{Organisation}` kept whole, `others` → "et al.", joined with ", "; year from `year`, else the first 4 digits of `date`; venue = `journal` / `journaltitle` / `booktitle` (when there is a title) / `school` / `institution` / `organization` / `publisher` / `howpublished` (theses without one: "PhD thesis" / "Master’s thesis"); url = `url`, else `https://doi.org/<doi>` (a doi given as URL or `doi:` is cleaned). LaTeX is turned into text: accent commands in all usual forms (`{\"o}`, `\"{o}`, `\"o`, `\c{c}`, `\v{s}` …) via Unicode combining marks + NFC, letters `\aa \AA \o \O \ae \ss \l` …, `\emph{}`/`\textit{}` etc. keep their text, `--` → –, `---` → —, `~` → space, escaped `\& \% \_`. Tested with Swedish/Nordic/German/Spanish names, `@string` journal macros, DOI-only entries and an organisation author. Volume, issue and pages are not kept (same fields as the old pattern).
- **Block `sbe/publications`** (server-rendered, `sbe_publications_render_block()`, editor side `assets/publications-block.js`; not in the inserter): `<div class="sbe-publications-section">` → h3 "Publications" (class `sbe-publications__heading`, attribute `heading`) → `<ul class="sbe-publications">` with per item the linked title (plain `span.sbe-publications__title` when there is no link), `<br>`, then "Authors (Year). *Venue*." - **The child theme carries what lives in the database here:** `theme.json` = the user global styles (full width, Manrope 300, bold headings, smaller font sizes, site-title hover); `style.css` = the Additional CSS; `templates/` = the DB templates Front Page, Pages, Single Posts, Single Project, Search Results; `parts/` = Header (navigation inlined: Page List + Search link, instead of `wp_navigation` 4) and Footer (address as placeholders, copyright `© [sbe_year] [sbe_site_name]`). `starter-pages/` = Home, News, Projects, People and Contact page content with placeholder text; the theme's admin notice "Create the pages" inserts them, fills in the project status term IDs (`__SBE_ONGOING__` / `__SBE_COMPLETED__`, they differ per site), sets Home as front page, orders the menu and sets the date permalinks.

When the design changes here, copy the change to the repo theme too (global styles → `theme.json`, Additional CSS → `style.css`, templates/parts → the matching file), and copy the plugin folder to `plugin/sbe-projects/` after each plugin version.

Under any other theme (e.g. the child theme) those pages rendered with no header or footer. Removed; WordPress fills in the active theme. No visible change on this site. ## Editing the database from Claude's device shell
- Don't open `wp-content/database/.ht.sqlite` for writing in place: SQLite can't delete its `-journal` file in the mounted folder, so the commit reports "disk I/O error" and leaves a hot journal that WordPress would use to roll the change back on its next request (happened 2026-10-15; fixed by truncating the journal to 0 bytes after checking the data was complete). Instead copy the DB to `/tmp`, edit and `pragma integrity_check` the copy, then `cp` it back (with Studio idle).
